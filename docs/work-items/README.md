# 编号任务书

本目录保存已经准备交给执行者的 `TRY` 与 `BUG` 任务书。`IDEAS.md` 是唯一总账，任务书负责一个编号的实施范围、技术边界、验收方法和执行结果。

## 查找任务

执行者收到编号后按以下顺序读取：

1. 在 [`IDEAS.md`](../../IDEAS.md) 中查找编号，确认类型、优先级、状态和关联项目。
2. 打开表格链接的同名任务书。
3. 核对当前分支、工作树、源码和已有证据。文档记录提供交接背景，当前仓库状态提供实施依据。

`IDEA` 需要先转换为新的 `TRY` 编号。没有任务书链接的项目仍处于讨论、复现或细化阶段。

## 任务书内容

每份任务书使用 `TRY-001.md` 或 `BUG-001.md` 形式的稳定文件名，并包含以下信息：

- 编号、类型、优先级、状态、来源和关联项目。
- 目标与真实用户路径。
- 已确认现状、用户报告和待确认判断。
- 实施范围、范围边界与推荐技术方向。
- 验收标准、测试范围和需要人工观察的结果。
- 执行约束、兼容边界与公开信息边界。
- 执行者回填的分支、提交、实际改动、验证证据和未完成项。

## 执行规则

- 一个任务书只负责一个编号。关联项目通过链接说明，各自维护状态和证据。
- 修改现有的唯一实现。新增类型、存储、视图或状态前，先确认现有实现无法承担该职责。
- 用户报告保持为用户报告，直至源码、测试或真实运行提供对应证据。
- 编译成功记录为构建证据。用户可见行为需要定向测试或真实屏幕观察。
- 动效需要观察连续帧，真机能力需要真机证据。缺少对应环境时直接记录未验证边界。
- 执行完成后回填任务书，并同步 `IDEAS.md` 的确认程度、状态与结果。结果只写当前有效结论。
- 文档按公开仓库内容处理。密钥、令牌、私人联系方式、保密资料和未公开 URL 不得进入任务书。

## 并行判断

修改同一模型、页面、存储格式或测试夹具的项目按顺序执行。互不依赖且文件范围独立的项目可以并行，交接前需要明确合并顺序和共同基线。

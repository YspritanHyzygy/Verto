## 目标

新建 `TranslationSession` 时历史记录为空。历史页面只显示用户在当前历史机制中实际保存的翻译。空列表在全部和收藏筛选下分别显示准确的空状态文案。

## 用户路径

1. 启动 Verto。
2. 打开文字翻译页面的历史记录。
3. 查看全部和收藏两个筛选状态。
4. 完成并保存一条翻译，再次打开历史记录并载入该条目。

## 已确认现状

- `Verto/Models.swift` 中的 `HistoryItem.today` 与 `HistoryItem.yesterday` 定义了三条演示翻译。
- `TranslationSession.historyItems` 直接使用这两组静态数据初始化，因此每个新会话都会带入三条记录。
- `HistoryView` 的空列表覆盖层固定显示 `暂无收藏`。全部筛选为空时需要显示 `暂无历史记录`。
- `VertoUITests.testTextDictationProducesResultAndFavoriteAppearsInHistory` 当前依赖演示数据产生的昨天分区。测试夹具需要改为由测试路径创建自己的前置数据。

以上结论来自 2026-08-28 对提交 `af52c10` 源码的静态核对。尚未运行当前构建观察真实历史页面。

## 实施范围

- 将生产 `TranslationSession.historyItems` 的初始值改为空数组。
- 从生产模型移除三条演示历史。预览或测试仍需要样本时，将样本放到对应预览或测试夹具中。
- 让 `HistoryView` 根据当前筛选显示 `暂无历史记录` 或 `暂无收藏`。
- 更新现有历史记录单元测试和 UI 测试，使测试通过公开保存路径建立数据。
- 保留 `TranslationSession.save`、收藏切换、历史载入和照片翻译存入历史的现有职责。

## 范围边界

- `TRY-006` 负责单条删除、批量删除和全部清空。
- 历史记录持久化、跨设备同步和恢复机制需要独立产品决定。
- 文字翻译首页的初始示例原文与译文属于其他范围。
- 历史卡片布局、筛选器样式和收藏交互保持现状。

`BUG-004` 与 `TRY-006` 修改同一模型和页面，两项按顺序执行。本任务合入并验收后再细化 `TRY-006`。

## 技术指导

- `TranslationSession.historyItems` 继续作为当前历史列表的唯一数据源。
- 演示数据不得留在生产数组后再由 `HistoryView` 过滤。
- 现有 `save` 方法继续承担去重与插入。测试通过用户操作或该公开方法创建记录。
- 空状态文案由当前筛选状态决定，沿用现有 `ContentUnavailableView`。
- 删除三条样本后检查依赖固定数量、固定文字和昨天分区的测试断言，并改为验证测试自己创建的数据。
- 历史数据继续由 `TranslationSession.historyItems` 单独持有，初始状态直接为空。

## 验收标准

- 新建 `TranslationSession` 后 `historyItems` 为空。
- 未保存翻译时，全部筛选显示 `暂无历史记录`，收藏筛选显示 `暂无收藏`。
- 保存一条翻译后，该条记录出现在今天分区，可以收藏、取消收藏和载入。
- 生产源码和本地化资源不再包含这三条演示历史文本。
- 历史 UI 测试不依赖预置的今天或昨天分区。
- 照片翻译保存历史的现有测试继续通过。
- 交付差异限于空初始历史、筛选对应的空状态和相关测试。

## 验证计划
